## 解锁 DNS 到底在做什么：它不改出口 IP，只改解析结果

很多人第一次接触这类服务，以为是某种代理。不是。解锁 DNS 干的事只有一件：把流媒体域名解析到一台能通过地区校验的机器上，再让那台机器替你转发流量。

完整链路拆开是两层：

1. **DNS 分流层**。用 smartdns 或者 dnsmasq 接管域名查询，命中 Netflix、Disney+、HBO 这类域名时，返回解锁机的 IP，而不是真实的 CDN 地址。
2. **反向代理层**。sniproxy 监听 80 和 443 端口，收到请求后按域名原样转发给真实站点，再把响应传回来。访问解锁机，效果等于访问流媒体网站。

所以判断一台机器“能不能被解锁 DNS 救活”，看的不是它的线路质量，而是它的 IP 有没有被流媒体拉黑、以及能不能连上解锁机。线路差但 IP 干净，配上解锁 DNS 一样能看；线路再好，IP 进了黑名单，DNS 也帮不上忙。

这套机制有个前提：**解锁机（或提供解锁 IP 的服务商）承担的只是域名解析和流量转发，你的实际出口仍然是那台被解锁机的 IP**。如果你用的服务是“按服务选地区”的类型，比如市面上 ISVORO 灰度测试中的解锁 DNS 平台，逻辑是把命中目标服务的域名指向对应地区的出口机，其他域名正常解析。这类平台化的做法在 2026 年确实越来越多，但功能细节各家不同，别拿别家的功能往 AKDNS 上套。

## 非 Akile 机器怎么配：改系统 DNS 就够，但有三处容易踩

如果你手上是别家的 VPS，最省事的做法是把系统 DNS 直接指到 184 段对应地区的地址，不用装任何软件。这是 AKDNS 这类服务的价值所在：不需要你有能解锁的机器，也不需要部署 sniproxy。

改完之后有三个点必须检查：

**第一，别让 `systemd-resolved` 把你的配置覆盖回去。** 在 Debian/Ubuntu 上直接改 `/etc/resolv.conf`，重启或者网络服务重载后经常被重置。稳妥做法是先把 `systemd-resolved` 停掉并禁止开机自启，再写死 DNS：

bash
systemctl stop systemd-resolved
systemctl disable systemd-resolved


写完之后用 `nslookup` 或 `dig` 验一下解析结果是不是落到了你填的那个 IP 段。有教程给的测试方法是 `nslookup ip.sb 127.0.0.1`，能解析出你自己指定的地址就说明分流生效。

**第二，53 端口别被占用。** 如果你的机器上已经跑了 dnsmasq、AdGuard Home、Pi-hole 这类服务，它们会抢占 53 端口，导致你的系统 DNS 设置和实际查询走的不是一条路。要么停掉本地 DNS 服务，要么在本地 DNS 里把流媒体域名转发到 AKDNS 的地址，别让两套解析同时生效。

**第三，如果机器上还要跑网站，80 和 443 会是冲突点。** 这一条主要针对自建解锁机（自己搭 sniproxy）的场景。用 AKDNS 这种托管服务时，80/443 的监听在对方那边，你不用管；一旦你自己装 sniproxy 做解锁机，这两个端口必须空出来并对外放开，否则转发不出去。

配好之后如果还是不解锁，先确认一件事：流媒体识别地区靠的是**出口 IP**，不是 DNS 服务器所在地。你填了美区 DNS，但机器 IP 是新加坡的，Netflix 认的仍然是新加坡。DNS 解锁能解决“IP 干净但地区不对”的问题，解决不了“IP 本身被判定为机房或代理”的问题。

## 自建解锁机还是用托管解锁 DNS：成本不在钱，在维护

这是搜索“解锁 DNS 服务”的人最常纠结的一点。两条路的差别不在技术难度，而在出问题的时候谁来修。

| 对比项 | 用 AKDNS 这类托管服务 | 自建解锁机（dnsmasq / smartdns + sniproxy） |
| --- | --- | --- |
| 需要一台能解锁的机器 | 不需要 | 需要，且 IP 要能通过地区校验 |
| 端口要求 | 无，本机只改 DNS | 53、80、443 都不能被占用，且要对被解锁机放开 |
| 配置工作量 | 改一个 DNS 地址 | 装 DNS 服务、装 sniproxy、维护域名列表 |
| 谁负责域名列表更新 | 服务方 | 自己，平台新增域名要手动补 |
| 解锁机宕机的影响 | 服务方切换 | 自己搭的解锁机挂了，被解锁机跟着不可用 |
| 被白嫖 / 被当 DNS 放大攻击跳板的风险 | 由服务方的白名单策略承担 | 自己负责，不开白名单就是敞开的 |
| 适合谁 | 单机、少量机器、不想维护 | 多台机器、需要精细控制地区与平台 |

自建方案里有一个容易忽略的风险点：**白名单**。有教程写得很直接，不开 DNS 白名单“会被别人白嫖，也可能被 D 哥用作 DNS 放大攻击”。如果你把 53 端口对着公网开放又不限制来源，别人拿你的机器当免费解锁 DNS 用是小事，被拿来做放大攻击、导致 IP 被打进黑洞才是麻烦。用 UFW 只放行被解锁机的 IP 访问 53/udp、80、443，是自建方案里必做的一步：

bash
sudo ufw allow from <被解锁机IP> to any port 53 proto udp


托管服务这边，白名单由服务方处理，你不需要开任何端口，也就没有这个暴露面。代价是地区、平台、可用性都跟着服务方的节奏走。

还有一个介于两者之间的做法，社区里叫“嵌套解锁”：把自己解锁机的上游 DNS 指向服务商提供的服务器，让下游机器都享受服务商的解锁权益。技术上可行，但原教程自己就标了“可能会违反商家的规则”。做之前先看服务条款，别把账号搭进去。

## 掉解锁了怎么办：按这个顺序排查，八成能定位

“会不会掉解锁”是这类服务最现实的顾虑。流媒体的封锁是持续动作，任何解锁 DNS 都不可能承诺永久有效。掉了解锁，按下面的顺序查，比到处换 IP 快得多。

**第一步，确认是全部掉还是个别平台掉。** 只掉 Netflix、Disney+ 正常，多半是平台侧更新了域名列表或改了校验逻辑；全掉，先怀疑 DNS 有没有被系统改回去。

**第二步，确认解析结果。** 用 `dig` 或 `nslookup` 查一个流媒体域名，看返回的是不是解锁服务该给的地址。返回的是真实 CDN 地址，说明 DNS 分流没生效，问题在本地配置；返回的是解锁地址但依然不解锁，问题在服务端。

**第三步，确认出口 IP 有没有变。** 换过机房、重装过系统、重启后拿到新 IP，都可能让原来的白名单绑定失效。用托管服务时，如果账号里绑定的是出口 IP，换 IP 后要同步更新。

**第四步，换地区试。** 手上有 184 到 190 这一整段，用香港的地址不解锁，换新加坡的试一次，能快速区分“这个地区被封了”还是“你的机器整体不行”。

**第五步，等或者问。** 平台侧的风控更新通常几小时到几天，服务方补域名列表也需要时间。这种时候频繁改配置只会让自己更乱。

有一个心态上的提醒：解锁 DNS 是租用服务，不是买断硬件。把它当成“按月或按年续的可用性”，比当成“一次配置永久有效”更接近实际。也正因为如此，选服务的时候，服务方补列表的速度和响应工单的态度，比一开始便宜几块钱重要得多。

## 常见问题

**AKDNS 现在还能免费用吗？**
Akile 自有机器和合作伙伴机器用的 83 段，在使用说明里标注为免费服务、无需添加白名单。但这个说明的时效需要自己确认，尤其是免费策略和地区可用性会变。稳妥做法是注册后在后台看当前状态，或者直接开工单问。

**不是 Akile 的机器能用 AKDNS 吗？**
可以，用 184 到 190 这一段，定位就是“为非 AKILE 机器提供解锁支持”。但这一段在说明里没有写清白名单步骤和收费口径，实际使用前要确认。

**一台机器能同时解锁多个地区吗？**
系统 DNS 只能填一组，想同时解锁多个地区需要在本机跑 smartdns 之类的分流服务，按域名把不同平台指向不同地区的解锁地址。多台机器的场景更适合单独搭一台 DNS 服务器，被解锁机只改系统 DNS 就行；单台机器就在本地装 smartdns。这个选择在教程里的结论是一致的：多台走集中式，单台走本地。

**填了 DNS 之后网站打不开了怎么办？**
先确认是不是把默认上游 DNS 也一起改掉了。正确做法是只把流媒体域名分流到解锁地址，其他域名仍然走 8.8.8.8 或 1.1.1.1 这类公共 DNS。全量替换 DNS 会有连带风险，除非你确认那台解锁服务对所有域名都能正常解析。

**解锁 DNS 和代理、机场有什么区别？**
代理改的是全部流量的出口，解锁 DNS 只改特定域名的解析结果，其他流量原样走本地网络。所以解锁 DNS 不会让你的机器“变成”某个国家的 IP，只是让流媒体以为你在那个地区。
